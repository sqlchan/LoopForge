# 维护与源码同步

LoopForge 以公共核心加部署专属适配器的方式维护。社区改动在本仓库中评审与测试；贡献者无需访问私有源码仓库或审计清单。

## 公共贡献检查

- 平台：Go 测试与 vet、API 与 runner 契约、全新安装、浏览器验收、公共内容检查与密钥扫描。
- Local：生成宿主一致性、安装与打包测试、Classic / Portable 行为契约与密钥扫描。
- 兼容性：记录 schema 迁移与破坏性的 API / runner 变更。保持现有安装命令与包名兼容。
- 保留第三方许可证与声明、贡献者署名与回归测试。

命令见[贡献指南](../CONTRIBUTING.md)，受支持的访问边界见[部署](deployment.md)。

## 仅维护者保留的记录

详细的源码版本、文件哈希、适配原因与排除文件清单属于本地维护记录。它们不提交到公共仓库，不进入 Docker 构建上下文，公共 CI 也不依赖它们。维护者保留私有备份，并在同步改动时使用本地审计。

移植共享修复时带上完整依赖链，用适配器与兼容性测试解决冲突，绝不把部署仓库覆盖到公共检出之上。不得导出凭据、生产数据或私有基础设施。审计标签必须反映实际同步的代码；仅修改记录的版本号不构成同步。

平台源码变更与 Local 包发布相互独立。合并平台 PR 不会发布新的 npm 包，也不会创建发布标签。
