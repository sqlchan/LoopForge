## 真实模型覆盖

按请求验证了 `deepseek-v4.1-flash` 模型，使用验收账号自身的 CodeBuddy 凭据与匹配的认证环境。源码与测试夹具中均未存储任何凭据。

- 一个 Agent 节点写出了声明的制品；后续脚本检查了该文件内容。套件检查了令牌用量、遥测与制品下载。
- 一个完整的交付 SOP 规划了一项改动、修复 Python 代码、独立评审、通过三项实际测试、等待人工审批并生成交付摘要。最后的脚本重跑了测试，并检查交付没有改变已验收的代码哈希。四个模型角色都记录了真实的令牌用量。
- 针对已结束的运行完成了 AI 评估。
- Assistant 回答了一个只读的项目问题，并通过 SSE 流式返回回复。
- 浏览器提交了一条真实的首页工作台消息，观察到回复完成，重新加载并检查了服务端会话。
- 通过真实浏览器 UI 完成了需求分析。
- Classic 与 Portable 的本地工作流各自在可弃置项目中的真实 CodeBuddy 进程内运行，修复了夹具、通过其测试，并保存了完成状态与交付制品。

这些测试覆盖所提供 CodeBuddy 模型。Codex 与 Claude 执行器有命令/协议与凭据边界测试；其付费服务未使用单独的提供商凭据进行验证。

## 检查覆盖的修复

首页输入框现在允许在模型配置完成前保存草稿，可跳转到凭据字段，并在凭据保存后更新能否发送的状态。从设置返回会保留草稿。与凭据相关的浏览器测试关闭了 trace 与截图。

头像回退与 Bot 刷新使用与现有内容安全策略兼容的外部 JavaScript 处理器。整视图浏览器检查会拒绝运行时与 CSP 错误。显式配置的 assistant 模型按其实际模型 ID 显示。

全新的 MySQL 安装在安装目录数据之前显式应用上游可观测性的生成列基线。首次安装与重复安装均已验证；应用启动仍不会执行数据迁移。

第三方声明维护在仓库根目录。打包时生成本地分发的声明，而不是再维护一份源码副本。本地组件的入口文档与共享项目策略保持合并管理。

首次访问尚无账号的安装时，会在浏览器中创建管理员；此后登录页提供自助注册，除非 `AGENTFLOW_ALLOW_SIGNUP=false`。首页显示可关闭的入门清单，跟踪模型密钥、项目、首次对话、首次运行与仓库连接，且在未配置密钥时输入框显示醒目提示。欢迎项目 seed 不再需要 `admin` 账号，安装器会在应用 seed 前等待 API 就绪（此前全新安装会因缺少 `run_telemetry` 表而失败）。没有照片服务时，头像在本地渲染，而不是返回 502。

由清单打开的仓库弹窗没有提交处理器，保存会重新加载页面；现在可以正常保存。仓库写入原本接受任何已登录用户；现在要求项目负责人或平台管理员。
