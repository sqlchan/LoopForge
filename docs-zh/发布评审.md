# 发布评审

本文记录 2026-10-16 的历史评审。原始范围、已修正的失败项以及未测试的外部服务边界见[验证记录](验证记录.md#全新安装与恢复的验收--2026-10-16)与[验收矩阵](测试/验收矩阵.md)。下面的历史计数与结果不能为后续提交背书；在合并或发布前，请针对确切的公开版本检查 CI。

## 结论

适合作为面向可信团队的初始公开自托管源码版本提交。仓库所有者要求进行最终评审，并于 2026-10-16 授权开启公开 PR。这是源码发布就绪性的结论，并不构成对每个提供方、操作系统或生产拓扑的认证；合并以及发布制品仍是独立的步骤。

受支持的访问模型是明确的：已登录用户可读取实例内的项目数据。项目写操作需要管理员、所有者或被授权的成员；只读成员身份不授予 Agent 执行权限。默认安装器绑定 localhost。在允许可信团队之外的访问之前，先关闭自注册（`AGENTFLOW_ALLOW_SIGNUP=false`）。默认容器配置会控制宿主 Docker 守护进程，只应由可信管理员操作。见[部署边界](部署.md#账号)。

## 最终的源码与部署评审

- 独立核对了全部 **1,718 个记录的源码 blob 哈希**与记录的主干。在托管 CI 兼容性修复之后，候选版本包含 1,464 个未改动的上游文件、180 个经评审的适配和 74 个记录的排除项，以及平台导出范围内 60 项经审计的公开新增内容。导出范围之外的私有部署文件仍被排除。未导入任何私有 Git 历史。
- 运行时包含持久的群组到 SOP 交接，并直接在 Docker 工作区中执行 SOP 脚本。Docker 测试覆盖非 root 执行和重新打开此前被遮蔽的工作区。MySQL 并发认领与租约恢复已显式验证。
- 源码同步后，预览仍在运行较旧的可执行文件。重建了服务与 runner/gate 辅助工具，重启了预览，并把其关键 JavaScript 资源与当前源码逐字节比较。交接验收用例现在覆盖当前端点行为。
- 修复了群组创建、角色派发、SOP 控制与交接重试中残留的只读成员权限缺口，并阻止只读成员执行与运行绑定的助手任务。测试覆盖只读成员/非成员被拒绝、所有者仍可访问；只读成员的读取权限保持不变。这项通用权限修复应回移到内部上游。
- 更新了源码审计记录与检查器：`--source` 现在既校验实际源码 blob，也校验远端提交标签。未重置任何无关的源码哈希。

## 证据的局限

- 外部知识检索/回写、企业通知和付费 Codex/Claude 服务缺少实时凭据。它们的协议/适配器测试不计为实时服务校验。
- 真实模型结果使用提供的 CodeBuddy 环境。四角色 Python 交付用例检查了实际测试、制品、审批和代码哈希；它不保证任意任务都能成功。
- 早先那次 47 分钟的运行在一个 Python 测试仓库上使用了前端 SOP 模板，并需要显式的人工澄清/验收。它展示了编排与恢复能力，而不是对每个前端框架或完全自主交付的校验。该次运行未创建任何 PR。
- Linux 容器/原生验收是此处检查的主要部署环境。macOS/arm64 辅助工具的交叉编译不是在每个受支持宿主上的运行时测试。
- GitHub 托管的 CI 必须校验提交的 PR。本次评审不发布任何包、镜像、标签或 GitHub Release。

## 最终提交评审 — 2026-10-16

最终评审修复了 PR #46 评审中同样指出的 runner 取消失效问题：取消现在会禁用已完成的上下文通道，由单个 goroutine 排空输出流并负责 `cmd.Wait`，早期控制失败会在返回前回收命令。聚焦的进程/托管 CLI 回归测试重复五轮均通过；取消和早期失败用例也在竞态检测器下重复三轮均通过。

另一次完整套件运行暴露了一个预览测试的竞态：预览在其异步工作区清理完成之前就已就绪。测试现在会等待持久化的清理标记与目录删除都完成后才关闭其存储；它重复 40 轮均通过。首次完整套件与修正后的最终套件分别记录在 [validation.md](验证记录.md#最终-pr-提交检查--2026-10-16) 中。
